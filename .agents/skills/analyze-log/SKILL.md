# Analyze Log Skill

This skill provides guidelines on how to interpret the debug logs generated by the Universal BoardBots Logger (`assets/logger.js`).

## How Logs Are Generated
The user's application (running on their browser/mobile) intercepts `window.onerror`, `unhandledrejection`, and explicit `logEvent()` calls, saving them to `localStorage`.
Because you (the AI) cannot directly access the user's mobile browser storage, the user will trigger a hidden UI interaction (tapping the screen 7 times) to copy the logs to their clipboard and paste them to you in the chat.

## Instructions for the Agent
When the user pastes a block of logs starting with timestamps like `[HH:MM:SS.mmm]`, follow this workflow:

1. **Acknowledge and Parse**: 
   - Acknowledge receipt of the logs.
   - Look for `ERROR:` or `PROMISE REJECT:` lines. These are critical exceptions caught by the global error handlers.
2. **Trace the DiceBox Initialization**:
   - Check if `initDiceBox() called` is present.
   - Look for `Fetching dice-box import...` and `DiceBox class imported successfully`. If it fails here, it's a CDN or CORS error.
   - Look for `Starting diceBox.init() race...`.
   - Check if it says `diceBox.init() RESOLVED` or `diceBox.init() TIMEOUT reached`. This indicates whether WebGL rendering succeeded or failed due to device constraints.
   - If it timed out, the fallback mechanism SHOULD have triggered later. Check if `diceBoxReady` became false.
3. **Trace Virtual Dice Roll**:
   - Check if `rollVirtualDice() called` is present.
   - Check the state of `diceBoxReady` at that exact timestamp.
   - If `diceBoxReady` is false, it means the app correctly bypassed the 3D dice and fell back to text. If the user still complains that "dice don't appear", the bug is in the HTML display logic of the fallback (e.g. `diceResultText` being hidden by CSS).
   - If `diceBoxReady` is true, look for `Calling diceBox.roll(...)` and `diceBox.roll resolved`. If it throws, look for `diceBox.roll catch:`.
4. **Formulate a Hypothesis**:
   - Compare the timing of the events. Did `rollVirtualDice()` happen *before* `initDiceBox()` finished?
   - Did the Promise reject with a specific Ammo.js or WebGL context error?
5. **Report to the User**:
   - Summarize the exact point of failure in non-technical terms.
   - Propose a fix (e.g. modifying the fallback logic, tweaking CSS, or adjusting async flow).

## Note
Do not attempt to run headless browser commands to fetch these logs yourself, as the bug often occurs specifically on the user's mobile device hardware (WebGL limits, iOS Safari strictness, etc.). Rely on the logs pasted by the user.
